# MicroDuck learning notes

## What this repository contains

This is an extension of the upstream MicroDuck RL project, based on commit
`b02fdea4902c2b93b7d34a83a6f05da4ececb7d3`. The initial local checkout is shallow;
its upstream commit and parent identity are preserved. This is not a robot or
reinforcement-learning stack implemented from scratch.

| Component | Purpose |
| --- | --- |
| `src/mjlab_microduck/` | Upstream robot definitions, tasks, rewards, and training integration |
| `scripts/train_live.py` | Local training-state viewer |
| `scripts/checkpoint_review.py` | Shared fixed evaluation profile and checkpoint playback |
| `scripts/review_viewer.py` | Native viewer command controls |
| `scripts/compare_*.py` | Earlier CPU deployment comparisons |
| `scripts/audit_*.py` | Diagnostic experiments; several expect preceding diagnostic artifacts |
| `scripts/aligned_cpu_bam.py` | Opt-in CPU controller with corrected friction indexing and training-compatible friction |
| `scripts/evaluate_sim_alignment.py` | Paired CPU/Warp regression using checkpoint 4500 |
| `scripts/test_aligned_cpu_bam.py` | Floating-base friction-index regression |
| `docs/learning/evidence/` | Selected recorded results, not generated by creating this repository |

## Recorded findings as of 2026-10-26

The completed learning run used 512 environments and 5,000 PPO iterations. The
last checkpoint is named `model_4999.pt` because indexing begins at zero.
Checkpoint 4500 was the balanced candidate under the chosen fixed evaluation;
4250 was faster forward but drifted substantially when asked to stop.

The follow-up used the same checkpoint and three paired initial states for each
of standing, forward movement, and turning. Four execution paths produced 36
30-second tests after 2 seconds of settling. All 36 survived these tests.
No training or checkpoint update occurred during that evaluation.

| Command / measurement | Original CPU | Aligned CPU | Warp with identical ONNX |
| --- | ---: | ---: | ---: |
| Stand: final displacement after 30 s | 23.3 cm | 23.7 cm | 17.7 cm |
| Forward target 30 cm/s: actual body-forward speed | 7.9 cm/s | 7.6 cm/s | 8.7 cm/s |
| Left-turn target 0.75 rad/s: actual yaw rate | 0.490 rad/s | 0.544 rad/s | 0.242 rad/s |

Alignment did not clearly reduce cross-engine differences. The aligned CPU
controller is a compatibility experiment, not a physical calibration of the
motor. Identical-state physics replay also found different foot contact
manifolds between CPU MuJoCo and Warp. Contact physics remains unresolved.

The ONNX export check compared 960 real observation samples against CPU PyTorch;
maximum action difference was approximately 1.2e-6. End displacement can hide
oscillation or circling, so the follow-up also recorded maximum offset and path
length. Three initial conditions are not independent training seeds. None of
these results prove real-robot performance or an overall win over the official
policy. Historical CPU and Warp reports must not be mixed into one ranking.

## Running the added tools

Use Linux/WSL with the project's dependencies installed. Follow the upstream
installation instructions below the introduction in the root README.
The evaluation scripts currently expect this run-relative location:

```
logs/rsl_rl/velocity/2026-10-25_18-12-33_rtx5060-walk/
  model_4250.pt
  model_4500.pt
  model_4500_eval.onnx
  model_4750.pt
  model_4999.pt
```

These artifacts are intentionally not in Git. Supply the original artifacts to
reproduce these exact results. For a different run, change the run selection
explicitly and record its checkpoint identity. Use the upstream `scripts/export.py`
export path so observation normalization is retained.

```bash
# Inference/playback only
uv run --locked python scripts/checkpoint_review.py play --iteration 4500 --viewer native --vx 0.15

# Paired regression: use a fresh output directory each time; run Warp first
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 uv run --locked python scripts/evaluate_sim_alignment.py --backend warp --out logs/alignment-repeat-01
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 uv run --locked python scripts/evaluate_sim_alignment.py --backend cpu --out logs/alignment-repeat-01

# Focused controller regression
uv run --locked python scripts/test_aligned_cpu_bam.py
```

Native fixed-preview controls: up/down adjust forward speed; left/right adjust
yaw rate; Space zeroes commands; T pauses; Enter resets. A zero command does not
guarantee the learned policy will stop drifting.

The live simulator used patched installed dependencies during diagnosis.
The repository preserves `uv.lock`, but dependency/source parity with a clean
installation must still be verified before claiming full reproducibility.
Creating this repository did not rerun training or the GPU evaluations.
